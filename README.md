# Home automation — ESP32 Web Flasher

Professional, lightweight browser flashing portal for an **ESP32 Dev Module** using **ESP Web Tools** and GitHub Pages.

## Important: manifest offsets

The requested offsets were supplied as strings such as `"0x1000"`. The current ESP Web Tools manifest format documents offsets as JSON numbers, so this production version uses:

```json
"offset": 4096
```

rather than:

```json
"offset": "0x1000"
```

Using strings is not the documented current format and can prevent the installer from interpreting the manifest correctly.

## Folder structure

```text
home-automation-esp-web-flasher/
├── index.html
├── manifest.json
├── .nojekyll
└── firmware/
    ├── sketch_sep24a.cpp.bootloader.bin
    ├── sketch_sep24a.cpp.partitions.bin
    ├── boot_app0.bin
    └── sketch_sep24a.cpp.bin
```

The four `.bin` files are your real compiled firmware files. They are not generated by this website package because the binary contents must come from your ESP32 build.

## 1. Put the real BIN files in `firmware/`

Copy these exact files:

```text
sketch_sep24a.cpp.bootloader.bin
sketch_sep24a.cpp.partitions.bin
boot_app0.bin
sketch_sep24a.cpp.bin
```

Do not rename them unless you also update `manifest.json`.

## 2. Check the manifest

`manifest.json` contains the four supplied flash locations:

```json
{
  "name": "Home automation",
  "version": "1.0.0",
  "builds": [
    {
      "chipFamily": "ESP32",
      "improv": false,
      "parts": [
        { "path": "firmware/sketch_sep24a.cpp.bootloader.bin", "offset": 4096 },
        { "path": "firmware/sketch_sep24a.cpp.partitions.bin", "offset": 32768 },
        { "path": "firmware/boot_app0.bin", "offset": 57344 },
        { "path": "firmware/sketch_sep24a.cpp.bin", "offset": 65536 }
      ]
    }
  ]
}
```

Hexadecimal equivalents are:

```text
4096   = 0x1000
32768  = 0x8000
57344  = 0xE000
65536  = 0x10000
```

## 3. Important ESP32 firmware compatibility note

Current ESP Web Tools documentation says modern ESP32 firmware may need to be merged first because the browser tool cannot patch flash mode, frequency, and flash size in the same way as `esptool`.

If the four-part manifest does not work with your particular firmware, create a merged image with `esptool`.

Example:

```bash
esptool --chip esp32 merge_bin \
  -o merged-firmware.bin \
  --flash_mode dio \
  --flash_freq 40m \
  --flash_size 4MB \
  0x1000 sketch_sep24a.cpp.bootloader.bin \
  0x8000 sketch_sep24a.cpp.partitions.bin \
  0xe000 boot_app0.bin \
  0x10000 sketch_sep24a.cpp.bin
```

Then use a manifest with one part:

```json
{
  "name": "Home automation",
  "version": "1.0.0",
  "builds": [
    {
      "chipFamily": "ESP32",
      "improv": false,
      "parts": [
        { "path": "firmware/merged-firmware.bin", "offset": 0 }
      ]
    }
  ]
}
```

Use the flash mode/frequency/size appropriate to the actual firmware and hardware. Do not blindly use the example values if your build uses different settings.

## 4. Create the GitHub repository

Create a new repository, for example:

```text
home-automation-esp-web-flasher
```

Upload:

```text
index.html
manifest.json
.nojekyll
firmware/
```

The `.bin` files must be uploaded as actual binary files, not copied into text files.

## 5. Enable GitHub Pages

In GitHub:

1. Open the repository.
2. Open **Settings**.
3. Open **Pages**.
4. Under **Build and deployment**, choose **Deploy from a branch**.
5. Select the branch containing these files, normally `main`.
6. Select `/ (root)`.
7. Save.
8. Wait for the Pages deployment to finish.

Your URL will normally be:

```text
https://YOUR-GITHUB-USERNAME.github.io/home-automation-esp-web-flasher/
```

If the repository itself is named `YOUR-GITHUB-USERNAME.github.io`, the URL can instead be:

```text
https://YOUR-GITHUB-USERNAME.github.io/
```

## 6. Verify every URL before flashing

After Pages is live, test:

```text
https://YOUR-GITHUB-USERNAME.github.io/home-automation-esp-web-flasher/manifest.json
```

It must display valid JSON.

Then test each binary:

```text
https://YOUR-GITHUB-USERNAME.github.io/home-automation-esp-web-flasher/firmware/sketch_sep24a.cpp.bootloader.bin
https://YOUR-GITHUB-USERNAME.github.io/home-automation-esp-web-flasher/firmware/sketch_sep24a.cpp.partitions.bin
https://YOUR-GITHUB-USERNAME.github.io/home-automation-esp-web-flasher/firmware/boot_app0.bin
https://YOUR-GITHUB-USERNAME.github.io/home-automation-esp-web-flasher/firmware/sketch_sep24a.cpp.bin
```

If any URL gives 404, fix the filename/path before testing the installer.

GitHub paths are case-sensitive in many deployment environments. Keep the spelling exactly consistent.

## 7. Test flashing

Use a current desktop Chrome or Edge browser.

1. Connect the ESP32 with a USB data cable.
2. Open the HTTPS GitHub Pages URL.
3. Click **Flash Firmware**.
4. Choose the correct serial port.
5. Approve the browser serial connection.
6. Let the installer finish.
7. Reset the ESP32.
8. Verify your firmware starts.

Close Arduino IDE Serial Monitor, PlatformIO serial monitors, and other programs that may already have the serial port open.

## 8. If the ESP32 will not enter download mode

For common ESP32 Dev Module boards:

1. Hold the **BOOT** button.
2. Press and release **EN/RESET**.
3. Keep BOOT held for a moment.
4. Release BOOT.
5. Start the browser connection again.

Exact behavior varies by board, so follow the board manufacturer's procedure if it differs.

## 9. “Failed to download manifest”

Check all of these:

- The Pages site is HTTPS.
- `/manifest.json` opens directly.
- The response is JSON, not an HTML 404 page.
- `manifest.json` is in the same directory as `index.html`.
- The `manifest` attribute is exactly `./manifest.json`.
- All `path` entries point to real files.
- The BIN files are committed and published.
- The repository branch/folder selected in Pages is correct.
- Hard-refresh the browser or use a private window after changing files.

## 10. Flashing connection problems

Try:

- Another USB data cable.
- Another USB port.
- Disconnect/reconnect the ESP32.
- Close serial-monitor software.
- Install the board's USB-UART driver.
- Manually enter bootloader mode.
- Use Chrome or Edge on desktop.
- Avoid USB hubs during troubleshooting.

## 11. ESP32-S3

This portal targets the requested **ESP32 Dev Module / ESP32** chip family.

Do not change the manifest to `ESP32-S3` simply because an S3 board is connected. S3 requires an S3 firmware and, depending on the connection, may use native USB CDC or UART. Build and publish a dedicated S3 variant if you later add S3 support.

## 12. USB drivers

If the serial port does not appear at all, identify the USB interface chip on the board and install its appropriate driver. Common ESP32 development boards use USB-UART bridges such as CP210x or CH34x, while some newer boards expose native USB.

The driver is an operating-system requirement; ESP Web Tools cannot install a missing USB driver.

## 13. Cache issues

After replacing `manifest.json` or firmware:

- Hard refresh the page.
- Try a private/incognito window.
- Verify the manifest URL directly.
- Confirm the new version field is updated.
- If a browser still appears to use old content, wait for GitHub Pages deployment to complete and retry.

## 14. Common mistakes

Do not:

- Put `manifest.json` in a different folder without updating the HTML.
- Rename a `.bin` file without updating the manifest.
- Upload a GitHub webpage URL as a firmware path.
- Use a `file://` URL for production flashing.
- Use Firefox for Web Serial flashing.
- Keep another application connected to the serial port.
- Flash while the USB cable is unstable.
- Treat an HTML 404 page as a firmware file.
- Replace the real ESP Web Tools element with a fake JavaScript button.

## 15. Project customization

Edit the text in `index.html` to change:

- Project name.
- Brand name.
- Supported board description.
- Documentation/tutorial link.
- Footer text.
- Theme colors.

The Flash Firmware control remains an actual `<esp-web-install-button>` component. The visible button is provided through its `activate` slot, so the click still enters the ESP Web Tools installation flow.
